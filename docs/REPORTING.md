# OneGl Professional Reporting

OneGl 的报告层用于把一次批次实验从“运行记录”提升为可复核、可交付的分析结果。

## 一键 HTML 报告

在任意批次详情页 `/batches/<id>`：

- **生成 HTML 报告**：浏览器本地生成一个自包含的 `onegl-batch-<id>-report.html` 并下载；
- **预览报告**：在新标签页打开同一份报告；
- 页面本身会自动加载“专业评估与建议方向”。

生成报告只读取 OneGl 已有的 `/api/batches/<id>` 数据，不会为了生成报告再次访问豆包，也不会把 Cookie、登录态、Token 或完整浏览器 Profile 写进报告。

命令行仍然支持：

```bash
npm run report:export -- --batch <id>
npm run report:html -- <snapshot.json> <report.html>
```

网页和命令行使用同一套 `src/report/evaluation.js` 与 `src/report/html-report.js`，避免两套评分口径。

## 报告新增统计

除了原有 RUN 提及率、PROMPT 覆盖、引用数与来源排行，报告还计算：

- 有效样本率、失败率、部分成功率；
- 引用解析完整度；
- 平均每个有效 Run 的可见引用密度；
- Top1 来源域名占比；
- 来源 HHI（Herfindahl–Hirschman Index）；
- 有效来源数 `1 / HHI`；
- 问题分类间提及率差距；
- 多账号间提及率差距；
- 目标文章最终引用率；
- OneGl 内部数据质量、品牌可见度、来源多样性与综合准备度评分。

## 评分不是豆包官方权重

所有评分都是 OneGl 的内部评估框架，只用于：

1. 在同一项目的不同批次之间做一致比较；
2. 快速识别数据质量、品牌可见度和来源结构的短板；
3. 为下一轮实验排序。

它们不是豆包官方评分，也不声称恢复了隐藏排序算法。

### 数据质量评分

主要考虑：

- 有效 Run 占请求样本的比例；
- 可比较 Run 的引用解析完整度；
- 失败 Run 比例。

当数据质量不足时，报告会优先给出 **P0：先修数据质量**，避免在脏样本上做业务推断。

### 品牌可见度评分

主要由：

- PROMPT 级提及覆盖；
- RUN 级品牌提及率；
- 若项目配置了目标文章，则加入目标文章最终引用率。

PROMPT 覆盖权重大于 RUN 提及率，因为重复问同一个问题可能抬高 RUN 指标，却不能代表整个关键词池。

### 来源多样性

报告使用 Top1 来源占比与 HHI 衡量引用是否过度集中。

- HHI 越高，来源越集中；
- `1 / HHI` 可理解为近似“有效来源数”；
- 高集中度不自动等于坏结果，但意味着对单一来源生态的依赖更强，需要单独观察。

### 综合准备度

综合准备度是 OneGl 内部汇总指标，由数据质量、品牌可见度、来源多样性以及（若存在）目标文章引用表现共同组成。

它适合用于同项目跨批次趋势，不适合跨行业直接比较。

## 建议方向

报告建议按优先级输出：

- **P0**：实验/数据基础问题，先修复再解释结果；
- **P1**：直接影响品牌可见度或引用结构的主要机会；
- **P2**：扩样、稳定性验证、长期优化。

每条建议包含：

- 观测证据；
- 建议动作方向；
- 下一轮应该验证的指标。

建议故意使用“测试 / 验证 / 观察”的语言，而不是把相关性描述成平台因果规则。

## 暖色调设计

Dashboard 与导出报告统一使用米白、陶土、琥珀与低饱和状态色：

- 米白底降低长时间阅读疲劳；
- 陶土色用于主动作与关键结论；
- 琥珀用于提醒和待验证项；
- 橄榄绿表示健康/较好；
- 砖红表示错误、阻塞与高优先级风险。

报告不依赖 CDN 或外部字体，便于离线归档与客户交付。

## 解释边界

即使综合评分很高，也仍需要：

- 跨时间重复同一 Prompt 池；
- 固定种子保持抽样可复现；
- 多账号验证个性化差异；
- 保存失败样本与引用解析口径；
- 将“进入候选池”与“最终用户可见引用”继续分开。

OneGl 的目标是让证据链更完整，而不是把黑盒系统包装成已经被完全破解。
