# OneGl Professional Reporting

OneGl 的报告层用于把一次批次实验从“运行记录”提升为可复核、可交付、可用于下一轮 GEO 调优的分析结果。

## 调优优先，而不是总分优先

报告的解释顺序固定为：

```text
Outcome
  -> Diagnostic
  -> Evidence
  -> Action
```

### Outcome：实际结果

回答“现在表现怎样”，包括：

- PROMPT 级品牌提及覆盖；
- RUN 级品牌提及率；
- 若已配置目标文章，目标文章最终引用率；
- 可见引用、来源与文章分布。

Outcome 只描述结果，不单独解释原因。例如“引用很多”不自动代表自有内容表现好，“提及率低”也不等于已经知道应该改哪个页面因素。

### Diagnostic：损失定位

回答“最可能卡在哪一层”，当前主要使用：

- 最弱问题意图及分类间提及率差距；
- PROMPT 覆盖短板；
- 自有/目标文章是否进入最终引用层；
- Top1 来源占比、HHI 与来源集中度；
- 账号间差异与样本信心。

报告顶部会给出一个“当前首要瓶颈”，用于排序下一步，而不是把多个指标平均成一句泛化结论。

### Evidence：能不能据此改内容

回答“这些观测是否足以支持页面改版”。这一层独立于业务结果，主要看：

- 有效 Run 与引用解析构成的数据质量；
- 候选页面证据覆盖；
- Candidate -> Citation 匹配覆盖；
- 因子 Evidence Gate；
- 因子证据质量与跨域一致性。

展示状态使用“先修数据 / 仅诊断 / 方向性诊断 / 可做受控实验”等语言。Evidence 不足时，弱相关信号可以保留供诊断，但不会升级成页面改版建议。

### Action：下一轮怎么验证

P0/P1 建议会直接进入调优摘要，每条包含：

- 当前观测证据；
- 建议动作方向；
- 下一轮验证指标。

Action 的目标不是宣称已经破解豆包排序规则，而是把可观察差异转成可复验实验。

## Prompt 优化机会矩阵

批次 Dashboard 与导出的优化 HTML 会把现有 Run 按 `Prompt + category` 聚合，直接回答：

> 下一轮先优化哪些问题？

当前状态分层为：

| 状态 | 优先级 | 含义 | 默认动作 |
|---|---|---|---|
| `DATA_GAP` | P0 | 没有有效 Run | 先补跑/修数据，不据此改内容 |
| `NO_MENTION` | P1 | 有有效 Run，但品牌 0 次提及 | 优先检查实体覆盖、直接回答与内容缺口 |
| `WEAK_MENTION` | P1 | 提及率 < 50% | 进入重点调优队列，固定 Prompt 复测 |
| `UNSTABLE_MENTION` | P2 | 提及率 ≥ 50% 且 < 100% | 继续重复，拆分随机性/账号差异 |
| `STABLE_MENTION` | WATCH | 当前有效 Run 全部提及 | 保留为对照组，不因“还能改”就盲目改 |

机会矩阵同时显示平均可见引用数，但**引用密度只是上下文，不是机会优先级或质量分**。一个 Prompt 即使触发很多外部引用，只要品牌从未被提及，仍然属于优先调优对象。

矩阵只使用已经存在于 Run 层的可观测字段：Prompt、分类、运行有效性、品牌提及和可见引用数量。它不会根据时间顺序、位置相邻或模型猜测制造 `Query -> Source` 关系。

如果 `/api/batches/<id>` 返回的 Run 数少于该批次实际分配数，矩阵会明确标成**局部诊断**，而不是把截断后的列表冒充完整问题池。

## 缺失值语义

OneGl 明确区分 `0` 和 `N/A`：

- `0%` 表示指标有合法分母，并且观测结果确实为 0；
- `N/A` 表示未配置、无合法分母或该证据层尚未建立；
- 缺失页面证据不会自动转成“页面没有该特征”；
- 未配置目标文章时 `0 / 0` 不得显示为 `0%`，也不得参与目标文章评分或触发相关优化建议；
- Run 没有可比较引用计数时，Prompt 机会矩阵中的引用密度显示 `N/A`，不能自动记为 0。

这个规则用于避免“没有测到”被误读成“表现很差”。

## 内部趋势评分降级为辅助指标

数据质量、品牌可见度、来源多样性与综合准备度仍然保留，但它们主要用于**同一项目跨批次趋势**。

报告与批次 Dashboard 不再把综合准备度作为第一结论。真正的调优顺序以上方的瓶颈、意图差异、Evidence Gate、Prompt 机会矩阵和下一轮实验为准。

## 一键 HTML 报告

在任意批次详情页 `/batches/<id>`：

- **生成 HTML 报告**：浏览器本地生成一个自包含的 `onegl-batch-<id>-report.html` 并下载；
- **预览报告**：在新标签页打开同一份报告；
- 页面本身会自动加载 **GEO 调优摘要**与 **Prompt 优化机会矩阵**。

生成报告只读取 OneGl 已有的 `/api/batches/<id>` 数据，不会为了生成报告再次访问豆包，也不会把 Cookie、登录态、Token 或完整浏览器 Profile 写进报告。

命令行仍然支持：

```bash
npm run report:export -- --batch <id>
npm run report:html -- <snapshot.json> <report.html>
```

网页、浏览器导出和 CLI HTML 报告共享同一套 evaluation / factor / optimization 组合逻辑，避免出现“Dashboard 一个口径、交付报告另一个口径”。

## 报告统计

除了 RUN 提及率、PROMPT 覆盖、引用数与来源排行，报告还计算：

- 有效样本率、失败率、部分成功率；
- 引用解析完整度；
- 平均每个有效 Run 的可见引用密度；
- Prompt 级有效 Run、提及率、提及稳定性与可比较引用密度；
- Top1 来源域名占比；
- 来源 HHI（Herfindahl–Hirschman Index）；
- 有效来源数 `1 / HHI`；
- 问题分类间提及率差距；
- 多账号间提及率差距；
- 目标文章最终引用率（仅在配置目标文章时）；
- 候选 -> 可见引用的匹配与页面因子证据；
- OneGl 内部数据质量、品牌可见度、来源多样性与综合准备度趋势评分。

## 评分不是豆包官方权重

所有评分都是 OneGl 的内部评估框架，只用于：

1. 在同一项目的不同批次之间做一致比较；
2. 快速识别数据质量、品牌可见度和来源结构的短板；
3. 为下一轮实验排序。

它们不是豆包官方评分，也不声称恢复了隐藏排序算法。

### 数据质量评分

主要考虑：

- 有效 Run 占请求样本的比例；
- 可比较 Run 的引用解析完整度；
- 失败 Run 比例。

当数据质量不足时，报告会优先给出 **P0：先修数据质量**，避免在脏样本上做业务推断。

### 品牌可见度评分

主要由：

- PROMPT 级提及覆盖；
- RUN 级品牌提及率；
- 若项目配置了目标文章，则加入目标文章最终引用率。

PROMPT 覆盖权重大于 RUN 提及率，因为重复问同一个问题可能抬高 RUN 指标，却不能代表整个关键词池。

### 来源多样性

报告使用 Top1 来源占比与 HHI 衡量引用是否过度集中。

- HHI 越高，来源越集中；
- `1 / HHI` 可理解为近似“有效来源数”；
- 高集中度不自动等于坏结果，但意味着对单一来源生态的依赖更强，需要单独观察。

### 综合准备度

综合准备度是 OneGl 内部汇总指标，由数据质量、品牌可见度、来源多样性以及（若存在）目标文章引用表现共同组成。

它适合用于同项目跨批次趋势，不适合跨行业直接比较，也不应直接翻译成页面改版指令。

## 建议方向

报告建议按优先级输出：

- **P0**：实验/数据基础问题，先修复再解释结果；
- **P1**：直接影响品牌可见度或引用结构的主要机会；
- **P2**：扩样、稳定性验证、长期优化。

如果 Evidence Gate 未通过，证据修复类 P0 必须先于业务内容改版；当没有 P0 时，摘要里的“下一轮优先动作”应尽量与当前首要瓶颈保持一致。

建议故意使用“测试 / 验证 / 观察”的语言，而不是把相关性描述成平台因果规则。

## 暖色调设计

Dashboard 与导出报告统一使用米白、陶土、琥珀与低饱和状态色：

- 米白底降低长时间阅读疲劳；
- 陶土色用于主动作与关键结论；
- 琥珀用于提醒和待验证项；
- 橄榄绿表示健康/较好；
- 砖红表示错误、阻塞与高优先级风险。

报告不依赖 CDN 或外部字体，便于离线归档与客户交付。

## 当前解释边界

即使内部趋势评分很高，也仍需要：

- 跨时间重复同一 Prompt 池；
- 固定种子保持抽样可复现；
- 多账号验证个性化差异；
- 保存失败样本与引用解析口径；
- 将“进入候选池”与“最终用户可见引用”继续分开；
- 不在 provenance 尚未验证时制造 Query -> Source 归因关系。

OneGl 的目标是让证据链更完整、让下一轮实验更明确，而不是把黑盒系统包装成已经被完全破解。
