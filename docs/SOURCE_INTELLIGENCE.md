# Automatic Cited-Source Intelligence

OneGl 的主分析链现在是：

```text
搜索问题
  -> AI 回答是否出现目标品牌
  -> 用户可见引用 URL
  -> 引用域名 / 文章
  -> 引用页内容摘要与 H1/H2/H3 结构
  -> 引用页是否包含目标品牌及其上下文
```

引用页内容分析属于**批次完成后的二级后台阶段**。它不参与豆包账号采集，也不会因为第三方网页无法访问而把原始 AI 搜索批次改成失败。

## 自动运行

升级后先执行：

```bash
npm run db:migrate
npm run worker
```

现有 `npm run worker` 同时监听两类队列：

1. 每个豆包账号自己的采集队列；
2. 一个独立的 cited-source intelligence 队列。

引用页队列默认并发为 `1`。Worker 每 15 秒对账一次：只要批次状态是 `completed` 或 `partial`，并且该批次的 `finished_at` 比最后一次引用页分析更新，就会自动创建新一代分析任务。

这意味着：

- 新批次完成后会自动分析引用页；
- 历史完成批次会在 Worker 启动后逐步补齐；
- 同一个批次重新执行后会自动产生新一代引用页分析；
- 重复对账不会重复创建同一代任务。

## 状态

`sampling_batches.source_intelligence_status` 使用以下状态：

| 状态 | 含义 |
|---|---|
| `idle` | 尚未调度，或等待自动对账 |
| `queued` | 已进入独立后台队列 |
| `running` | 正在读取用户可见引用页并生成派生情报 |
| `completed` | 所有可见引用页均完成内容画像，或没有引用页需要分析 |
| `partial` | 至少一部分引用页成功，但部分页面无法完成分析 |
| `failed` | 本轮没有任何引用页形成可用内容画像，或后台任务本身失败 |

批次页会直接显示该状态。处于 `queued`、`running` 或 stale 状态时，页面每 5 秒自动刷新情报卡；分析结束后无需手工刷新浏览器。

## 数据边界

自动分析只使用 `citations.visible_to_user IS NOT FALSE` 的最终用户可见引用，不把 retrieval candidate 或隐藏来源混入主报告。

对第三方页面只保存派生字段，例如：

- 短内容摘要；
- H1/H2/H3 标题层级；
- 正文长度、段落、列表、表格、FAQ 等结构信号；
- 内容类型画像；
- 目标品牌出现次数、位置、匹配词与短上下文。

不保存第三方页面完整 HTML 或完整文章正文。

品牌检测复用项目的主品牌、别名、产品别名与排除正则，保持 AI 回答品牌检测和引用页品牌检测口径一致。

## 抓取与安全

引用页抓取：

- 只允许公开 HTTP/HTTPS 地址；
- 检查并遵守 `robots.txt`；
- 每次重定向都会重新做公共地址校验；
- 有响应大小和超时限制；
- 同域请求有节流；
- 登录墙、robots 阻止、动态壳页面、过大页面等会记录为未解析，而不会影响 AI 搜索批次本身。

## 重跑保护

每次自动分析都会记录：

- `source_intelligence_generation`；
- 任务创建时对应的批次 `finished_at` 快照。

Worker 在开始和完成任务时都要求批次完成时间仍然匹配该快照。如果同一批次已经重新执行，旧任务会被视为 superseded，不能把旧分析状态写成当前最新结果。

## 手动命令

自动模式是默认路径。手动命令保留用于故障排查、验证或强制刷新：

```bash
npm run source:intelligence -- --batch <batch-id>
npm run source:intelligence -- --batch <batch-id> --refresh
```

正常使用不再要求批次完成后手动运行这条命令。

## 解释边界

OneGl 可以可靠陈述：

- 某个搜索问题对应的有效 AI 回答是否出现目标品牌；
- 同一问题对应 Run 实际展示了哪些引用 URL；
- 某个引用 URL 被哪些问题引用；
- 引用页自身是否包含品牌，以及页面结构是什么。

除非平台提供句子到来源的明确 provenance，否则不能进一步声称“某一个 URL 单独导致了 AI 提及品牌”。引用来源与品牌提及在同一回答中共同出现，是可观测关系，不自动等于因果关系。
