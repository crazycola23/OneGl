# 匿名面容量与风控验收设计（2026-10-16）

目的：把「一个 IP 能用几次、多久恢复、会不会永久废」从经验判断变成**可证伪的判据**，
让采购 IP 套餐这件事有数字依据，而不是靠感觉。

术语：

- **会话** = 浏览器窗口（一次冷启动 + 一个身份 + 一个出口）
- **对话** = 会话里的一次提问

---

## 1. 三个待回答的问题

| # | 问题 | 为什么重要 |
|---|---|---|
| Q1 | 一个会话里问 N 条对话，比 N 个会话各问 1 条更耐用吗？ | 决定买「少量长效 IP」还是「大量短效 IP」 |
| Q2 | 被风控之后多久恢复？ | 决定 IP 数量 = 并发数 × 几 |
| Q3 | 反复压测会导致出口永久失效吗？ | 决定「遇到风控就抛掉」的成本 |

---

## 2. 验收判据（每条都必须可证伪）

### Q1 —— 窗口内复用的价值

**前置条件**：出口必须先通过**干净性检查** —— 连续 2 条单会话探测都成功，
**且检查必须在开跑前 5 分钟内完成**。

时效性是 2026-10-16 补的：当天 04:29 探针确认恢复，05:34 开跑 B 组，
结果**第一条就被限流** —— 一次在 T+32 通过的检查，证明不了 T+95 仍然干净。
干净性不是一次性的状态，是有保质期的。

**对照**：

| 组 | 会话数 | 每会话对话数 | 总对话 | 间隔 |
|---|---|---|---|---|
| A | 8 | 1 | 8 | 45s |
| B | 2 | 5 | 10 | 45s |

**计量单位必须是「对话数」**，不是「会话数」—— 两条臂的会话数不同，用会话数比会得出假结论。

**判据（看 B 组第几条对话首次失败）**：

| B 组首次失败 | 结论 | 可证伪的表述 |
|---|---|---|
| ≥ 8 条 | 窗口内复用显著更耐用 | 「限制按会话记，不按 IP 记」 |
| 4–5 条 | 限制按「每 IP 每窗口 M 条对话」记 | 「窗口间切换不省额度，只省时间」 |
| ≤ 2 条 | 窗口内连续提问**更可疑** | 「同一会话内连问会加速触发风控」 |

**重复要求**：每组至少跑 2 次。两次结论冲突 → 判为「不稳定」，先提高样本再下结论。

### Q2 —— 冷却时长

**方法**：`node tools/probe-recovery.mjs --interval-min 15 --max-minutes 150`
（每个周期只发 1 条对话 —— 探测不该比实验本身还贵）

**判据**：**连续 2 次成功**才算恢复。单次成功不算 —— 同一天已经出现过
「同一配置 3 次成功后接 2 次失败」的抖动，单点成功可能是漏网。

**分档**：

| 恢复耗时 | 结论 | 采购动作 |
|---|---|---|
| ≤ 30 分钟 | 短冷却 | IP 数 = 并发数 × 2 |
| 30–120 分钟 | 中冷却 | IP 数 = 并发数 × 4 |
| > 120 分钟 | 长冷却 | 按「1 IP ≈ 1–2 个窗口/天」采购 |

### Q3 —— 永久失效（今天无法验收）

需要跨 24 小时观测，**本次会话内不可能得出**。方法：
对同一出口，在 T+0（触发）/ T+1h / T+3h / T+8h / T+24h 各探 2 条。

**判「永久失效」必须同时满足**：

1. T+24h 的 2 条**全部失败**；
2. 失败形态是**硬墙或静默软墙**（`local_` + 无首 token），不是限流文案；
3. 期间没有其他变量变化（出口、指纹策略、请求量都固定）。

只满足 1、2 条 → 判「长冷却」，**不是**永久。这条区分直接决定要不要把 IP 从池子里删掉。

## 3. 实验卫生（今天已经踩过的坑，写成规则）

1. **先证明出口干净再开跑** —— 否则样本被上一个窗口污染，「第 2 条就失败」会被误读成「连问更可疑」
2. **一次只改一个变量**：出口 / N / 间隔 / 指纹策略，禁止同时动两个
3. **失败必须分四类记**，处置完全不同：

   | 形态 | 判据 | 处置 |
   |---|---|---|
   | 限流 | 文案「当前服务访问频繁」→ `RATE_LIMITED` | 降速 + 冷却 |
   | 静默软墙 | URL `/chat/local_` + 首 token 永不出现 | 冷却，不立即删 |
   | 硬墙 | `?from_logout=1`、区域封禁页 | 废弃该组合 |
   | 验证码 | 页面出现人机验证 | 废弃，且停止该出口 |

4. **每条样本必须留 URL** —— URL 形态是目前唯一的客观判据。
   截至 2026-10-16：失败 **10 条全部 `/chat/local_`**，成功 **30+ 条全部 `/chat/<纯数字>`**
5. **每组至少 2 次重复** —— 同一配置今天既出现过 3 连成功，也出现过连续 2 次失败
6. **额度也是成本**：探测用 1 条、实验用 N 条，不要用「多问几次求稳」代替判据

## 4. 2026-10-16 的基线数据（可直接引用）

| 观测 | 数值 |
|---|---|
| 单条/会话模式下的阈值 | **4 次成功后**开始被静默丢弃（同一窗口内） |
| 当天累计成功 | 7 次匿名问答（含 1 次 33 条引用） |
| 首 token 延迟（成功） | 5s / 5s / 11s |
| 首 token 延迟（软墙） | 永不出现（等到 180s 超时） |
| 限流后恢复 | 有 1 次约 1.5 小时完全恢复；另有 1 次 15 分钟后**仍未**恢复 |
| 出口类型 | 成都电信 **IDC**（AS38283）—— 机房段，非住宅 |
| **惩罚会随累计使用升级** | 同一天：早先软墙后 **16 分钟**恢复；几小时后同样形态、空闲 **65 分钟**仍在限流 |
| ~~AS 类型与可用性相关~~ **（已降级为假设，证据不足）** | 同一时刻：主机 `120.41.214.161`（AS4134 普通宽带）成功、代理 `125.64.14.30`（AS38283 机房段）限流。**但两者当天用量历史完全不同**（代理约 20 次、主机 2 次），而且随后**主机 IP 第 2 条也被限流** —— 一个带混杂变量的瞬时对照不能支撑采购决策 |
| **共享池的 IP 不是你的首访** | 供应商池是共享的，提取到的 IP 可能刚被别的客户用过。平台看到的不是「新用户」，而是「这台 IP 今天第 N 次」。→ 「1 IP 1 次」的设计意图与实际效果可能不一致，这一条尚未实测 |

## 6. 待补进判据的两条（2026-10-16 观测到，尚未定案）

1. **干净性检查有时效**：必须在开跑前 ≤5 分钟完成；超过就重测。
2. **惩罚等级会随累计使用上升**：同一个出口，冷却需求从 16 分钟涨到 >65 分钟。
   这直接改变 Q3 的问法 —— 不是「会不会永久废」，而是**「累计用多久之后连冷却都救不回来」**。
   要测它，需要的不是单次冷却曲线，而是**跨天的累计用量 → 恢复耗时**对照表。

   对采购的含义：「遇到风控就抛掉」不是优化项，而是必需项；单价之外还要算
   **单 IP 的累计寿命**（一个 IP 一共能安全服务多少次对话）。

## 7. 采购前必验三项（2026-10-16 定，不看供应商的宣传语）

买任何代理之前，先花最小成本验这三项。三项都过再谈量；任一项不过就换供应商。

| # | 验什么 | 怎么验 | 不过的后果 |
|---|---|---|---|
| 1 | **AS 是家宽段还是机房段** | 拿到 IP 后查 `ip-api.com/json/<ip>`，看 `as` 字段：`AS4134 CHINANET BACKBONE` 类=普通宽带；含 `Internet Data Center`/`IDC`=机房 | **未定案**（见 §4 的降级说明）。查它是因为**便宜**，不是因为它已被证明更差 —— 下面的首访对照实验才能定案 |
| 2 | **IP 有效期是否覆盖一个会话** | 单会话墙钟实测 **50–70 秒**（冷启动 35–45s + 回答 10–33s）。IP 时效必须 ≥ 2 分钟并留余量 | 30–60 秒档会在回答途中失效，会话作废 |
| 3 | **是否支持会话粘性 / 自主切换** | 问清楚：一个会话期间 IP 会不会变；换 IP 有没有频率上限；有没有可程序化的切换接口 | 按请求轮换的隧道代理会直接毁掉会话 |

补充：

- **不要单独看「不限量」三个字** —— 有一家的「不限量」是「每日提取次数不限」，价格按
  `IP池单位 × 单价 × 天数` 计（8 元/单位/天），并不便宜。
- **优先住宅/家宽产品线**，而不是短效机房池；这跟第 1 项的实测结论一致。

### 7.1 定案实验：控制用量历史的首访对照（未执行）

要判断「段/池级信誉」是否影响第一个请求，必须把**用量历史**这个混杂变量控住：

| 组 | 样本 | 每个 IP 用量 | 比较 |
|---|---|---|---|
| 机房段 | 20 个从未在本机用过的 IP | **只做 1 次**对话 | 两组成功率 |
| 家宽段 | 20 个从未在本机用过的 IP | **只做 1 次**对话 | |

关键点：单 IP 只用一次 → 理论上不触发按频率的限制，测到的就是**段/池级信誉**。
代价 40 次对话额度；结论直接决定「该不该为家宽多付钱」。

⚠️ 这个实验有一个**无法完全消除的局限**：无法证明这些 IP 在**平台侧**也是首次使用 ——
供应商池是共享的，只有统计意义上的对比（若机房组成功率显著更低，才说明有段级影响）。
